**Date**: 2026-07-04
**Status**: Decided

## Context

EstimateKit holds client estimation data and serves on a public hostname through the shared tunnel. Every surface (the SPA, `/api/*`, `/mcp`) needs gating before the instance serves anything, and a misconfigured deployment must never be silently open.

## Decision

HTTP Basic auth gates every route with a single shared credential, fail-closed: enforcement turns on when `ESTIMATEKIT_AUTH_USER` and `ESTIMATEKIT_AUTH_PASSWORD` are set, turns off only with an explicit `ESTIMATEKIT_AUTH_DISABLED=true` (local dev and tests), and with neither, protected routes answer 503. The health endpoint (`/api/health`) stays exempt so orchestration probes keep working. The chart names `auth.existingSecret: estimatekit-auth`, provisioned out of band.

## Rationale

- Estimation data is client-confidential; the app refusing to serve unauthenticated is self-contained safety, independent of edge infrastructure.
- Fail-closed means a deployment with a missing Secret is closed, never open, which is what makes publishing the hostname safe.
- One mechanism covers all surfaces, including MCP clients, which pass the `Authorization` header natively.

## Alternatives considered and rejected

- **Edge-only gating** (access proxy in front): leaves the app open inside the cluster and couples safety to infrastructure the app cannot verify. Edge SSO can still be layered on top.
- **A per-user model**: there is one operator; a shared credential matches the actual trust boundary, and per-user identity can arrive later if warranted.
